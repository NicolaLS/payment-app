# ADR 0003: Blip separates public storage from credentials

Status: accepted for the initial extraction

SQLDelight is the durable source for public connection profiles, payment
attempts, bounded transition history, contacts, and shortcuts. Preferences are
typed, non-transactional UI settings only. JSON aggregates are not used as a
database.

Each provisioning creates a new `ConnectionId`. SQL stores the Blink account
and wallet IDs but never the API key. Android encrypts the API key using a
non-exportable AES-GCM key generated by Android Keystore. The encrypted payload
is addressed only by `ConnectionId` in a private preferences file. API key
wrappers and onboarding actions redact their string representation.

The Android application disables backup and cleartext traffic. No database,
preference, route, saved state, diagnostic, or log may contain a plaintext API
key. Removing a connection deletes its key but retains payment provenance and
unresolved attempts; without that historical credential they remain honestly
unknown instead of being looked up through a replacement connection.

There is deliberately no legacy credential or database migration. Reinstall
and extraction users reconnect from scratch.

Rejected legacy choices include secret-bearing navigation, plain settings
credentials, implicit backup, and deleting old payment truth on reconnect.
